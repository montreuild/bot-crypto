#    python3.14 -m venv /opt/crypto_bot/.venv
#    source /opt/crypto_bot/.venv/bin/activate
#    pip install -r requirements.txt

#  On macOS (Homebrew):
#    brew install python@3.14
#    python3.14 -m venv .venv
#    source .venv/bin/activate
#    pip install -r requirements.txt
#
#  On Windows (Git Bash or PowerShell):
#    See docs/DEMARRAGE_WINDOWS.md for full guide.
#    1. Install Python 3.14 from https://www.python.org/downloads/
#       (check "Add Python to PATH")
#    2. py -3.14 -m venv .venv

#    4. pip install -r requirements.txt

#  NOTE : les versions sont épinglées pour garantir la reproductibilité
#  en production. Pour mettre à jour, testez d'abord dans un environnement

# -- Web / API -------------------------------------------------------
# fastapi 0.115.0 → 0.141.1 : imposé par la remédiation starlette ci-dessous.
# 0.115.0 demandait `starlette>=0.37.2,<0.39.0`, ce qui rendait impossible toute
# montée de starlette au-delà de 0.38.x. 0.141.1 demande `starlette>=0.46.0`
# sans borne haute.
fastapi==0.141.1
# starlette : transitive de fastapi, épinglée ICI malgré la règle « seules les
# dépendances directes sont épinglées » (cf. en-tête). La règle suppose que les
# transitives sont contraintes par leur parent — ce n'est vrai que d'un côté :
# rien n'empêche une réinstallation de résoudre vers une version incompatible si
# un AUTRE paquet la tire. Le pin reste donc justifié.
#
# 0.38.6 → 1.3.1 : 0.38.6 cumulait 8 vulnérabilités connues (PYSEC-2026-161,
# -248, -249, -1941, -1943, -2280, -2281), le job `security` de la CI échouait
# dessus.
#
# ⚠ Historique : une précédente tentative de passage en starlette 1.3.1 avait
# cassé la collecte des tests API sur `TypeError: Router.__init__() got an
# unexpected keyword argument 'on_startup'`. La cause a disparu — plus aucune
# occurrence de `on_startup` / `on_shutdown` / `@app.on_event` dans `app/`,
# le cycle de vie passe par `lifespan` (cf. `_lifespan` dans app/api/main.py).
# Vérifié : 1392 tests passés, 3 ignorés, à l'identique d'avant la montée.
starlette==1.3.1
uvicorn[standard]==0.30.0
# S6-09 (29/07/2026) — FIN JINJA2 : le frontend Next.js (frontend/) sert
# maintenant tout le HTML/CSS/JS. Les templates Jinja2 ont été supprimés
# (cf. docs/FIN_JINJA2.md). Jinja2 reste épinglé comme dépendance
# TRANSITIVE de FastAPI (utilisée pour /api/docs et /api/redoc — la doc
# Swagger auto-générée). Notre code ne l'importe plus directement.
# SEC-010 : 3.1.4 est vulnérable (CVE-2024-56201 / CVE-2024-56326, contournement
# du bac à sable de template). Le plancher de l'audit était 3.1.5 — on prend 3.1.6
# parce que 3.1.5 est elle-même vulnérable à CVE-2025-27516 (même famille) : viser
# le plancher exact aurait imposé un second bump immédiat.
jinja2==3.1.6
# 0.0.22 → 0.0.32 : 5 vulnérabilités connues (PYSEC-2026-3036 à -3040), la plus
# haute exigeant 0.0.31. On prend la dernière publiée.
python-multipart==0.0.32
slowapi==0.1.9
# Charge le `.env` généré par setup.sh (WEB_API_KEY, clés exchange) avant
# l'expansion des `${VAR}` de config.yaml. Sans lui le fichier était écrit
# puis ignoré, et le démarrage web échouait sur la garde OPS-02.
# 1.1.1 → 1.2.2 : PYSEC-2026-2270.
python-dotenv==1.2.2

# -- Exchange --------------------------------------------------------

# -- Data / Compute --------------------------------------------------
